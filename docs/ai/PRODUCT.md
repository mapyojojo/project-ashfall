# Product — Project Ashfall

v0.8.0を基準に、Producer・Director・Reviewerが判断するときに守る方向性を整理する。これは実装仕様や数値調整の指示ではない。現在の操作・成立条件は [README.md](../../README.md)、責務は [ROLES.md](ROLES.md)。

## 守りたい体験

**Ash Stitch / 灰縫いがゲームの中心。** 自動射撃で生きた敵へ灰紋を仕込み、配置を読み、群れや狙った対象を横切って回収・炸裂させる因果関係を保つ。射撃だけで戦闘が完結する方向にはしない。

**移動・位置取りも戦闘の一部。** WASD移動、照準、敵との距離、突進の角度、着地後の位置が次の仕込みと灰縫いにつながる。仕込み中や待機中も動く理由があり、固定砲台で特殊攻撃を待つだけの体験を目指さない。

**成功の違いと危険を読める。** 灰紋、経路、予告、着地、炸裂、追加攻撃を理解でき、危険を取る見返りと次に取る行動が伝わる。派手さが敵弾・地面攻撃・自機・成功条件の読み取りを失わせない。

## ランごとの分岐

| 方向 | 狙う体験 |
| --- | --- |
| 拡散 / Triple Stitch | 群れへ広く仕込み、まとめて縫って安全と展開を得る |
| 濃縮 / Dense Stitch | 少数へ灰を積み、狙った相手への高火力を育てる |
| 連続 / Flow | 返し縫い・連環縫いなどをつなぎ、次の仕込みと攻撃を繰り返す |

系統は混成できる。成功名と強化の系統は完全な同義語ではなく、固定クラスでもない。取得した強化から「次に欲しいもの」を想像し、ランごとに異なる仕込み方・経路・連続攻撃へ育つことを重視する。

育ったビルドで「壊れた」ような強さや連続炸裂を感じられることは歓迎する。その爽快感と、別の選択・位置取り・危険を読む価値が両立しているかを判断する。

1ランで全アップグレードを取得することを通常の成長目標にしない。終盤にも欲しい候補や未完成の組み合わせを残し、次のランへ選択をつなぐ。これは全取得が絶対に不可能という新しい制約ではなく、現在のビルド分岐を守る方向性。

## 現時点の優先順位

1. **Game feel**：灰縫いの手応え、テンポ、攻撃をつなぐ気持ちよさ。
2. **Readability**：仕込み・経路・成功・危険・成長を読み取れること。
3. **Build diversity**：異なる組み合わせと判断に意味があること。
4. **Maintainability**：回帰を確認でき、変更箇所と責務が分かること。
5. **Additional content**：上記を支える追加要素。

Producerが優先順位を変える場合は対象スプリントに理由を記録し、この文書と [AGENTS.md](../../AGENTS.md) を揃える。文書の更新だけでゲーム仕様の変更が承認されたとは扱わない。

## 自動検証と実プレイ

自動テストは成立条件、状態、保存互換、日英表示と挙動、乱数、回帰、負荷などの証拠を作る。通し自動操作のクリア数や攻撃回数は、面白さ、公平性、初見理解の証明ではない。

実プレイは手応え、視認性、待ち時間、選択の面白さ、支配的戦略、認知負荷を判断する。AIは仮説と観察項目を用意し、Producer / Playtesterの判断を最終判断として次スプリントへ返す。
