# AI Development Roles

この文書は責務と判断権限の正本。共通の作業ルールは [AGENTS.md](../../AGENTS.md)、工程は [WORKFLOW.md](WORKFLOW.md)。役割は会話の担当を表し、別サービスや自動エージェントの起動を要求するものではない。

| 役割 | 担当 | 責務 | 成果物・判断 |
| --- | --- | --- | --- |
| Producer / Playtester | 人間 | 方向性・優先順位、実プレイ評価、AI提案の採否、プロダクトの最終判断 | 感想、Scopeの決定、プレイテスト結果、次スプリントの選択 |
| Director | ChatGPT | 感想・要望を整理し、目標と仕様へ変換。両レビューを統合し、ゲームデザインの方向性を守る | スプリント案、実装への引き継ぎ、統合した判断材料 |
| Implementer | Codex | リポジトリ調査、実装計画、承認されたScopeのコード・文書変更、自動テスト、動作確認、結果報告 | 差分、検証結果、未確認事項、Git状態 |
| Game Design Reviewer | ゲームデザイン担当のAI | Game feel、理解、リスク / リターン、ビルド多様性、支配的戦略、相乗効果、強弱、認知負荷 | [Game Design Guide](REVIEW-GUIDE-GAME-DESIGN.md) に沿った設計レビュー |
| QA / Engineering Reviewer | 技術・回帰担当のAI | 不具合、回帰、edge case、save/load、ブラウザ、i18n、入力、テスト不足、リリース上のリスク | [QA Guide](REVIEW-GUIDE-QA.md) に沿った技術レビュー |

## 境界

- Directorは原則として実装しない。ゲーム仕様の新しい決定やScopeの拡大は、Producerの判断材料として提示する。
- Implementerは承認されていない新しい要件を追加しない。承認済みScope内の実装方法は調査と根拠に基づいて選べる。
- Game Design Reviewerはコード品質を原則評価しない。体感を自動テストだけから断定せず、未プレイの推測を明記する。
- QA / Engineering Reviewerは技術品質と回帰を評価する。不具合起因でないバランス変更は提案しない。
- Reviewerは指摘と提案を返す。レビュー依頼だけで実装・仕様変更・公開を行わない。指摘がない場合は明確に「重大な懸念なし」と記録する。
- 問題が両領域に関わる場合は原因と影響を分ける。例：追加攻撃の回数が仕様と違う原因はQA、仕様どおりでも選択肢を支配する懸念はGame Design。Directorが関連指摘をまとめる。

## 別視点のレビュー

レビューが必要なスプリントでは、実装会話とは別の会話・コンテキストで担当を明示する。モデルや製品の指定は不要。Game DesignとQAはそれぞれのガイドを使い、相互の結論を前提にせず確認する。実装担当の自己レビューは独立レビューとして数えない。

渡す最小情報は現在のスプリント、基準コミットと対象差分、関連する仕様、検証結果と制限。実装理由やテスト成功の説明だけで判断せず、アクセスできる実物と証拠を確認する。AIがリポジトリへアクセスできなければ、人間が必要な差分・画像・記録を渡し、読めていない範囲を残す。

レビュー結果は現在のスプリントのReview Resultsへ貼るかリンクする。別ファイルが必要なときだけ追加する。別会話への受け渡しは手動でよく、今回の仕組みではAI同士の自動会話は行わない。

Producerの明示した方針を守りつつ、レビュー同士で意見が分かれたらDirectorが事実・仮説・選択肢を整理する。面白さや方向性の最終判断はProducerへ戻す。
