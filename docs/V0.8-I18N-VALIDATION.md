# v0.8 検証結果と残した境界

基準: v0.7.1 / `1058b3b1b7d1b884da9b3e24551b843a9d19cb41`。バージョン: v0.8.0。

## ファイルと依存

読み込み順は `index.html` 内で version → storage → ja/en辞書 → i18n → upgrades → relics → audio → ui → input → game。すべてclassic script。HTTPとfile起動で同じソースを使い、fetch/import/外部依存は追加していない。

- `game.js`: ラン・戦闘・乱数・Canvas描画・状態遷移・抽選と獲得・記録加算。従来の約900行から約780行。
- `input.js`: keyboard/mouse/blur/visibility/fullscreenイベントと繰り返し入力の抑制。状態遷移はgameのコールバック。
- `ui.js`: 固定文言、タイトル記録、装備、HUD、カード/Lv詳細、ポーズ関連ラベル、結果のDOM描画。読み取りと画面操作のコールバック。
- `audio.js`: Web Audio初期化、mute、tone、縫いの各SFX。発音タイミングはgameに残し、音の乱数は戦闘乱数と独立。
- `storage.js`: 既存metaの読書きと独立した言語設定。保存拒否は従来と同様に吸収。
- `upgrades.js` / `relics.js`: 効果と安定したID/番号。表示getterが辞書を参照。
- `i18n.js` / `i18n/ja.js` / `i18n/en.js`: 291組のキー、`{name}`形式の補間、変更通知、保存済み設定の優先、日本語へのfallback。

## 言語と保存

タイトルの「日本語」「English」をクリックする。画面再読み込みは不要。`html.lang`と選択ボタンの`aria-pressed`も同期する。初回はブラウザ言語がjaなら日本語、それ以外は英語。保存した選択を次回から優先する。

言語は `ashfall.language` に追加。既存 `ashfall.v1` のJSONは言語変更で書き換えず、marks/best/wins/runs/relicと未知の付加フィールドも保持する。装備番号2は引退済み予約、番号3は割れた銃身。migration不要。解放は印数から従来通り導出する。

カードを更新するだけで再抽選しない。結果を再描画しても残火印を再加算しない。言語切替UIはタイトルだけに置いた。APIでラン中に切り替えた場合はHUD/カード/結果が即時更新するが、すでに発生した短命の通知・浮き文字は寿命まで元の言語を保持する。次の通知とCanvasラベルは新言語になる。

## ブラウザ検証の再実行

1. ターミナルで `npm start` を起動し、localhost:4173を利用できる状態にする。
2. 普段使いとは別の専用Edgeプロファイルを作り、CDPポート9223で非表示起動する。既存の通常ブラウザへ接続しない。
3. 別ターミナルで `npm run test:i18n:browser`。続いて既存の `npm run test:public`、`npm run test:feedback`、`npm run test:browser`、`node tests/clarity-check.cjs`、`node tests/hazard-check.cjs` を1つずつ実行する。同じページを操作するため並列実行しない。
4. テスト専用ブラウザとサーバーを終了する。検証JSONとv0.8画像はリポジトリ内に出力する。

PowerShell起動例（Edgeのインストール先に合わせて変更する）:

```powershell
Start-Process -FilePath 'C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe' -WindowStyle Hidden -ArgumentList '--headless=new','--disable-gpu','--remote-debugging-port=9223','--user-data-dir=D:/develop/project-ashfall/.browser-v08','--no-first-run','http://localhost:4173/?test'
```

Node.js 22以降のfetch/WebSocketを使う。ポートを変える場合は `ASHFALL_CDP_PORT` を設定する。通常入力検証は最大約8.5分かかり、途中の自然な死亡は結果として記録する。i18nのレイアウト検証だけはfixture内で描画ループを停止し、実入力と表示を確定させる。

## コード側に残す表示

ASHFALL/PROJECT等のロゴ、装飾の英語スローガン、READY/ON/OFF/LV、キー名、矢印/図形、時刻/割合の書式は両言語共通の短い記号・ブランド/数値表示として残す。プレイヤー向け日本語文字列は本体JS/HTMLから抽出済み。辞書のHTMLは管理された`<b>`/`<br>`等の固定表示に限定し、ユーザー入力をHTMLとして挿入しない。

## 今回残した技術的負債と次の候補

全面的なmodule/bundler導入、Canvasレンダラーの分割、戦闘状態のクラス化、ポーズ/画面遷移の状態機械化は見送った。安定した戦闘ループを保持するため、UIへのコールバックは多めで一部のgame関数は互換用ラッパー。fullscreen API呼出とボタンの結線はgameに残す。Web AudioのfeedbackSpecは戦闘演出と共有のためgameから渡す。

次はCanvas描画の純粋な部分、画面遷移/Fullscreen操作、通知をキーと値で保持する表示層を順に分離するとよい。対応言語追加はまず辞書を作り、同じキー/補間の検証を通す。今回は英語の読みやすさを自動検証と目視で確認したが、英語母語話者のレビュー、物理Esc、Chrome/Firefox/Safariでのv0.8新規検証は別途必要。
