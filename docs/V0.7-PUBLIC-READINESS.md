## 2026-10-03 — 全画面・ポーズUXとブラウザ確認の追記

main `3ff193c` を基準に `work/v0.7-fullscreen-pause-ux` で修正。全画面切替を共通処理へまとめ、タイトルとポーズの両画面へ「全画面にする / 全画面を解除」を表示する。実際のFullscreen API状態で両方のラベルを同期する。

Pは全画面中もポーズ / 再開。Escは通常画面でポーズし、ポーズ中の再開には使わない。全画面中のEscはブラウザに任せ、preventDefaultやキーボードロックで奪わない。全画面解除を検知した時点でプレイ中なら、既存の共通ポーズ処理を呼ぶ。再開はPまたは「戦闘へ戻る」。解除イベントとEscの到着順序が違っても、Escで直後に再開しない。

自動ポーズの対象はプレイ中だけ。タイトル・装備・ヘルプ・強化選択・結果・既存のポーズは維持し、blur / visibilitychangeが続いても再開しない。切替でランを作り直さず、強化候補と音声状態を保持する。解除は状態変化イベントから判断する。[Fullscreen API仕様](https://fullscreen.spec.whatwg.org/#api)

## 説明と挙動の照合

| 箇所 | 確認結果と対応 |
| --- | --- |
| 灰の伝播 | 上限に達した敵への仕込み命中で、周囲145以内の上限未到達の敵へ1灰。上限の敵がいるだけで周期的に広がるわけではない。「命中で」を新文へ加え、範囲と間隔はLv詳細へ移した。数値は変更しない。 |
| 留める白灰 | 実際に炸裂が命中したときの減速。説明も命中時の効果として揃えた。 |
| 二重の縫い目 | 0.5秒後の逆向き再炸裂は前線通過時の命中。残光で継続ダメージを与える文言は使わない。 |
| 密縫い / 密縫いの極意 | 密縫いは最初から存在する成功判定。「密縫いの極意」は成功時の威力倍率を伸ばす強化。README・用語表で成功と強化を区別し、ヘルプの成功名「密縫い」は維持する。 |
| 濃灰の刻印 / 灰圧 | 濃灰の刻印のLv3でも通常敵の上限は9灰。番人・炉心はさらに6灰を蓄えられるため、灰圧の12灰段階を狙える。強敵向けという説明を保つ。 |
| 飛び散る残灰 | 灰縫いの経路の始点・中央・終点の炸裂時に発射。逆向き再炸裂・一点穿ちには追加されない。本文は「経路上から」、Lv詳細は「3か所から」で説明する。 |
| 返し縫い / 連環縫い | 2秒以内の追加入力。連環には返し縫いが必要で、通常 → 返し → 連環の最大3回。持ち越した灰は密縫い・灰圧・早縫いの新しい回収量に数えない。 |
| 消弾 | 飛翔弾を対象とする。地面の予告・範囲攻撃は残る。ヘルプとREADMEに共通の注意を残す。 |
| 火種の余韻 | 灰を使った灰縫いで回復時間を更新する。引き継いだ灰でも回復するため「新しい灰紋の回収」に限定しない。 |

## 配布ファイル

ゲームの必要ファイルは同じ階層の5ファイル。ビルドやnpm installは不要。

```text
index.html
style.css
version.js
upgrades.js
game.js
```

ZIP配布ではStart.bat、README.md、CREDITS.mdとREADMEが参照する文書・画像も同梱する。ライセンス確定後はLICENSEを含める。開発用の.git、.codex、work、tests、検証JSON、node_modulesはゲーム起動に必要ない。Nodeで起動する開発者用配布ならserver.jsとpackage.jsonも含める。

相対パスの通常scriptで読み込むため、file起動と公開先のサブディレクトリで同じ構造を使える。バージョン取得にfetchやES Modulesは使わない。

### GitHub Pages（将来の公開手順）

1. ライセンスとレビューを終え、公開するコミットを所有者が決める。
2. 上記5ファイルをルートに置く配布元を準備する。README・クレジット・LICENSEを含め、必要なら空の.nojekyllを置く。
3. リポジトリのPages設定で配布元ブランチのルートを選ぶ、または同じファイル一式をActionsの静的成果物として渡す。
4. 公開URLで開始・音声・全画面・記録・サブパス上の読み込みを確認する。

Pagesは公開元のルートにindex.htmlを置ける。現状のdocsフォルダにはゲーム入口がないため、docsをそのまま公開元に選ばない。設定や実際の公開は今回実施しない。[GitHub公式の作成手順](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)

### itch.io（将来の公開手順）

1. 5ファイルをZIPのルートに置く。フォルダごとを一段深く入れない。
2. HTMLゲームのプロジェクトにZIPをアップロードし、ブラウザ内で遊ぶファイルとして指定する。
3. 1280×720を目安に埋め込み寸法・全画面の可否を設定し、プレビューで操作とパネルを確認する。
4. ブラウザごとの入力・音声開始・保存の可否を確認し、試作版の表記・制限・クレジット・利用条件を揃えてから公開する。

index.htmlを入口にしたZIPで配布できる。[itch.io公式HTML5ガイド](https://itch.io/docs/creators/html5)。埋め込み環境は未検証で、今回アップロードや下書きページ作成は行わない。

### ZIP（将来の配布手順）

1. 必要5ファイルと文書・画像・Start.bat・確定後のLICENSEを集める。
2. ZIPを作り、別フォルダへ全展開してindex.htmlを直接起動する。
3. WindowsならStart.batも確認する。タイトルの版、ヘルプ、開始、再挑戦を確認する。
4. バージョンをZIP名に含め、配布ページにPC用・途中セーブなし・試作版と記す。

Start.batは既定ブラウザでindex.htmlを開く。ゲーム用ファイルは外部通信を行わない。保存先が変わると残火印などの記録も別になる点をREADMEへ残す。
